# Framework mapping

> Generated by `tools/build_mapping.py` from `data/controls.json`. Do not edit by hand.

The toolkit's **32 controls** are written for a small business, in our own words. Each one is tagged with:

- **CSF 2.0:** the NIST Cybersecurity Framework 2.0 subcategories it achieves (the backbone, [ADR 0001](adr/0001-nist-csf-backbone.md)).
- **ISO 27001:** ISO/IEC 27001:2022 Annex A control numbers (`Cl.` = a mandatory clause). Numbers only; the standard's text is not reproduced.
- **CIS IG1:** CIS Controls v8.1 Implementation Group 1 safeguard numbers.
- **PDPA:** the Malaysian PDPA duty it supports (see [pdpa-summary.md](pdpa-summary.md)).

**How references are checked.** NIST publishes official mappings from CSF 2.0 to ISO/IEC 27001:2022 and to CIS Controls v8.1 (its CSF 2.0 informative references, extracted to `data/csf2-olir.json`). A reference with no mark appears in NIST's mapping for at least one of the control's CSF subcategories. A reference marked **\*** is our own mapping: it is not in NIST's file for those subcategories. NIST's CIS v8.1 references cover only 48 of 106 subcategories, so many CIS links are necessarily our own. Note: NIST's file lists clause "6.13" for ID.RA-06, which looks like a typo for 6.1.3. It is shown as given in the reference table.

**Check results:** ISO references 37 confirmed / 22 own mapping; CIS references 15 confirmed / 48 own mapping. CIS IG1 coverage: **56 of 56** safeguards (all covered). CSF 2.0 subcategories used: 42 of 106.
